# Reparación de páginas web poco accesibles en el cliente: herramientas y técnicas

Fecha: 2026-10-31. Investigación previa al complemento «Arreglo web» de Tiresias.

Tiresias presenta la web a través de su propio búfer virtual (`src/tiresias/browse/buffer.py`), construido sobre el árbol de accesibilidad que expone el navegador (UIA/IAccessible2). No puede modificar el DOM ni el CSS de la página; solo decide *qué* presenta al usuario y *cómo* (nombre, rol, nivel de encabezado, regiones, qué nodos entran en el búfer). El objetivo de esta nota es inventariar qué hacen las herramientas que «arreglan» páginas en el cliente (extensiones de navegador, complementos de JAWS/NVDA, funciones de Chrome/Edge/Narrador) y separar las técnicas que Tiresias puede reproducir sobre su búfer de las que exigen tocar el DOM y, por tanto, quedan fuera de alcance o se delegan a herramientas externas.

## 1. Herramientas estudiadas

| Herramienta | Tipo | Qué hace | Técnicas concretas |
|---|---|---|---|
| **Web Access for NVDA** (Accessolutions) | Complemento de lector | «Módulos web» por sitio (un `.json` por sitio en `webModule/`, elegido por URL o título de ventana) formados por reglas. | Seis tipos de regla (`ruleTypes.py`): `Marker`, `Zone`, `Page main title`, `Page secondary title`, `Page type`, `Parent element`. Criterios: `text` (con prefijo `<` busca en el elemento anterior, útil para etiquetar campos), `role`, `tag`, `id`/`className` con comodín `*`, `src` de imágenes, `states`, `relativePath`, `index`. Acciones: `moveto`, `speak`, `sayall`, `activate`, `mouseMove`, más acción automática al cargar. Propiedades: `customName` (renombrar), `customValue`, `sayName`, `skip` (saltar en navegación rápida), `multiple`, `formMode`, `priority`. **Mutaciones** (`controlMutation.py`) que reescriben los atributos del nodo en el búfer sin tocar el DOM: `button`, `link`, `heading.1`…`heading.6`, `labelled` (pone el nombre de la regla), `section`, `landmark.region`, `landmark.nav.named/unnamed`, `table.data`/`table.layout`. Las zonas acotan la navegación a una región de la página. |
| **JAWS Flexible Web** | Función del lector | Asistente (JAWS+Espacio, X) para «ocultar» un elemento o «empezar a leer en» un elemento; se puede ocultar solo el primero o «todos los similares» (por ejemplo todos los anuncios). | Cambios temporales que se pierden al salir, salvo que se guarden como regla con alcance página / sitio / todos los sitios; JAWS avisa con un sonido cuando aplica una regla; deshacer última personalización. El ocultado opera sobre el búfer virtual de JAWS, no sobre la página. |
| **JAWS Custom Labels** | Función del lector | Insert+Ctrl+Tab asigna una etiqueta propia a casi cualquier elemento alcanzable con Tab (campos sin etiqueta, botones gráficos, enlaces). | Se guardan en archivos `.jsi` de `PersonalizedSettings`, por dominio; borrado por página desde Insert+F2. Equivale a `customName` de Web Access. |
| **JAWS Verbosidad web / Text Link Verbosity / prompt de formularios** | Ajustes del lector | Verbosidad separada para gráficos, enlaces de texto, campos de formulario y botones (Insert+V). Para campos: usar `label`, `title`, «ambos si difieren» (Label+Title, Label+Alt). Si no hay etiqueta, JAWS lee el atributo `title` al enfocar. | Heurística histórica de JAWS: deducir la etiqueta de un campo por el texto inmediatamente anterior o por la cabecera de columna cuando no hay `label`/`aria-label`. Smart Navigation: tratar tablas y controles como unidades al navegar con flechas. |
| **NVDA (comportamiento base)** | Lector | Enlace con imagen sin `alt`: anuncia «gráfico sin etiqueta» y lee el nombre de archivo de la imagen; si el enlace tiene `title`, lee el `title`. Anuncia «se puede hacer clic» cuando Chrome marca el nodo como pulsable (conmutable en Formato de documentos). | Nombre deducido en cascada: `aria-label`/`aria-labelledby` → contenido → `title` → nombre de archivo/último tramo de URL. |
| **AI Content Describer** (cartertemm), **Online Image Describer**, **NVDA AI Assistant** | Complementos NVDA | Describen con modelos multimodales (GPT-4o, Gemini, Claude, Azure Vision…) el objeto navegador, la ventana, la pantalla completa o el portapapeles (NVDA+Shift+Y, NVDA+Shift+I). | Captura de pantalla del rectángulo del objeto → modelo de visión → texto hablado. No tocan el DOM; funcionan sobre cualquier aplicación. |
| **axSGrease** (James Teh, NV Access) y userscripts de Greasy Fork | Userscripts (Tampermonkey/Greasemonkey) | Scripts por sitio (GitHub, Plex, Sched, Culture Amp…) que arreglan la página. | Patrón: selector CSS → asignar `role`, `aria-label`, `aria-level`, `aria-haspopup`; reaplicar con `MutationObserver`. Modifican el DOM. |
| **AltSpark, WebA11y, Web Enhancer, A11y Fix-It Assistant** | Extensiones Chrome (2024-2025) | Rellenan `alt` ausente, enlaces «clic aquí», encabezados genéricos y `aria-label` de campos con IA (Gemini o IA local de Chrome); modo automático por sitio. | Reescriben atributos del DOM en tiempo de ejecución. |
| **Accessibility Insights, axe DevTools, WAVE, Sa11y** | Extensiones de auditoría | Detectan problemas (nombres ausentes, contraste, «encabezados falsos») y los muestran al autor; no los corrigen. | Sa11y marca como posible encabezado el texto corto en negrita o de letra mayor que el entorno; axe tiene la regla `p-as-heading` (párrafo con `font-size` mayor, `bold` o `italic` respecto a los vecinos). Son heurísticas reutilizables para deducir encabezados. |
| **Consent-O-Matic** (Univ. Aarhus) / «I don't care about cookies» | Extensiones | Responden o quitan ventanas de consentimiento de cookies. | Consent-O-Matic: lista JSON de reglas por CMP (más de 200: OneTrust, CookieBot, UserCentrics…) con `detectors` y métodos `OPEN_OPTIONS`, `DO_CONSENT`, `SAVE_CONSENT`, `HIDE_CMP`; pulsa botones y aplica la elección del usuario. IDCAC: listas de filtros CSS que ocultan el banner e inyecta scripts para desbloquear el desplazamiento. Ambas tocan DOM/CSS. |
| **Vista de lectura de Firefox / Modo lectura de Edge / Just Read / Mercury Reader** | Funciones del navegador o extensiones | Extraen el contenido principal y lo presentan limpio. | Readability.js: puntúa párrafos (1 + comas + min(longitud/100, 3)), propaga a ancestros, descarta nodos con clase/id tipo `comment`, `footer`, `menu`, `sidebar`, `sponsor`, penaliza bloques con muchos enlaces, elige el subárbol de mayor puntuación. Crea una página nueva. |
| **HeadingsMap, Landmark Navigation via Keyboard or Pop-up** | Extensiones | Muestran esquema de encabezados o regiones y permiten saltar a ellas. | Solo lectura del DOM existente; equivalen a la lista de elementos del lector. |
| **Chrome «Get image descriptions from Google»** (2019) | Función del navegador | Para usuarios de lector, envía a Google las imágenes sin `alt` y añade la descripción al árbol de accesibilidad con el prefijo «Appears to be» / «Appears to say». | Opt-in; solo inglés; «No description available» cuando el modelo no está seguro. |
| **Edge «Get image descriptions from Microsoft»** (2022) | Función del navegador | Igual que Chrome, con Azure Computer Vision; descripción en 5 idiomas y OCR en 120. | Prefijos «Appears to be…» / «Appears to say…»; prefiere siempre el `alt` del autor. |
| **Narrador** | Lector | «Get image descriptions, page titles and popular links» (envía la imagen a Microsoft; Narrador+Ctrl+D) y, desde 2025, descripciones ricas locales en Copilot+ PC, extendidas a todo Windows 11 en 2026 (Narrador+Ctrl+S para la pantalla). | Lo del etiquetado de botones sin nombre con IA en 2021-2022 **no se ha podido confirmar** en fuentes públicas; solo consta la descripción de imágenes. |
| **Heurísticas del propio Chromium** | Navegador | El árbol de accesibilidad marca como `clickable` cualquier elemento con escuchador `click` o `mousedown` (no `keydown`, y no se hereda del padre); un `<a>` sin `href` con escuchador de clic pasa a rol `link`; el nombre de controles sin etiqueta se calcula «from contents»; `role="heading"` sin `aria-level` recibe nivel 2. | Es la base sobre la que Tiresias puede decidir «genérico pulsable → botón». |

## 2. Técnicas reproducibles desde un lector de pantalla (sin tocar el DOM)

Todas estas operan sobre lo que Tiresias ya tiene: nodo UIA/IA2, sus propiedades y su posición en el búfer. Web Access for NVDA demuestra que basta con reescribir `role`, `level`, `name`, `landmark` y `table-layout` en el nodo del búfer.

1. **Nombre deducido para controles sin nombre** (botones, enlaces, imágenes). Cascada: `aria-label` / `aria-labelledby` → texto de los hijos (incluido `alt` de imágenes y `title` de SVG) → atributo `title` → `alt` → nombre de archivo de la imagen sin extensión ni guiones → último tramo de la URL del enlace (`/productos/zapatos-rojos` → «zapatos rojos») → texto del `tooltip`. Es lo que NVDA y JAWS ya hacen parcialmente; la novedad es hacerlo sistemático y legible (quitar `_`, `-`, `%20`, extensiones, hashes).
2. **Etiqueta de campo por contexto**. Si un campo no tiene nombre: tomar el texto estático inmediatamente anterior en el búfer (en la misma línea o la anterior), o el texto a la izquierda en la misma fila visual, o la cabecera de columna/fila si el campo está en una tabla, o el `placeholder`. Es la regla `text` con prefijo `<` de Web Access y el etiquetado automático de JAWS. Marcar la etiqueta como deducida (por ejemplo, anteponer nada pero exponerla con menor confianza en el modo de depuración).
3. **Genérico pulsable → botón**. Si el nodo es `generic`/`div`/`span`, Chromium lo marca `clickable` (o UIA expone `InvokePattern`), tiene nombre (propio o deducido) y es pequeño (pocas palabras, no contiene bloques de texto), presentarlo con rol botón y permitir activarlo con Intro desde el búfer (ya hay «hacer clic» mediante `Invoke`/clic de ratón en el centro del rectángulo). Si tiene `aria-haspopup` o hijos con `menuitem`, botón de menú. Si es una imagen pulsable sin nombre, botón gráfico con el nombre del archivo.
4. **Encabezado deducido por formato**. Texto corto (menos de ~12 palabras, sin punto final) que es un bloque propio y cuyo tamaño de letra o peso (`FontSize`, `FontWeight` vía `TextPattern`/IA2 text attributes) es claramente mayor que el del cuerpo (mediana de la página): presentarlo como encabezado. Nivel por tamaño relativo: el mayor de la página → h1 (o h2 si ya hay un h1 real), siguiente escalón → h3… Es la heurística de Sa11y y de la regla `p-as-heading` de axe; conviene no aplicarla si la página ya tiene una jerarquía razonable de encabezados reales.
5. **Ocultar superposiciones y ruido en el búfer**. Reconocer banners de cookies/consentimiento por texto («cookies», «consentimiento», «aceptar todo», «política de privacidad») y por `id`/`class` (`cookie`, `consent`, `gdpr`, `onetrust`, `cookiebot`, `usercentrics`, `didomi`, `sp_message`) y colocarlos al final del búfer o saltarlos en navegación rápida, con una orden para «ir a la ventana de cookies» y aceptar/rechazar. Es lo que hace Flexible Web («ocultar») sin cerrar el banner de verdad. Igual para barras de «suscríbete», chats flotantes y «compartir en redes».
6. **Empezar a leer en un punto / zonas**. Por sitio, recordar «al cargar, mover el cursor al primer `main`, o al encabezado nivel 1, o al elemento que cumple la regla X» (Flexible Web «start reading at», Web Access `Zone` + acción automática `moveto`). Si no hay `main`, deducir la región principal con el criterio de Readability: el ancestro con mayor densidad de texto en párrafos y menor densidad de enlaces.
7. **Regiones deducidas**. Bloque al principio con muchos enlaces y poco texto → navegación; bloque al final con enlaces legales → pie; `id`/`class` que contengan `nav`, `menu`, `sidebar`, `footer`, `header`, `content`, `main`, `article` → región correspondiente. Permite que las teclas de región funcionen en páginas sin `landmarks`.
8. **Tablas de maquetación vs. datos**. Tabla sin `th`, sin `caption`, con una sola fila o columna, o con celdas que contienen bloques grandes → tratar como maquetación (no anunciar coordenadas). Web Access expone `table.layout`/`table.data` como mutación manual; se puede automatizar y dejar que el usuario fuerce lo contrario.
9. **Descripción de imágenes y controles con IA**. Como AI Content Describer, Chrome y Edge: capturar el rectángulo del nodo (o la pantalla), enviarlo a un modelo de visión local o remoto y anunciar con prefijo «Parece ser…» / «Parece decir…». Opt-in, con caché por URL de imagen para no repetir. Aplicable también a iconos sin nombre (describir «icono de papelera» → botón «Eliminar»).
10. **Renombrar/ocultar manualmente y guardar por sitio**. Órdenes al estilo JAWS Custom Labels / Web Access: «dar nombre a este elemento», «ocultar este elemento y los similares», «hacer encabezado de nivel N», «convertir en botón», con persistencia por dominio (JSON por sitio en el perfil de Tiresias, identificando el elemento por `id`, `class`, `role`, texto, `src` o ruta relativa, como hace Web Access). Esto cubre lo que la heurística no acierte.
11. **Deducir el título de la página** cuando `<title>` es genérico («Inicio», nombre del sitio): usar el primer h1 o el nombre de la región `main` (reglas `Page main title` y `Page secondary title` de Web Access).

## 3. Técnicas que requieren tocar el DOM o el CSS

No son viables en Tiresias porque el lector solo ve el árbol de accesibilidad y no puede ejecutar código en la página. Se indica la alternativa.

| Técnica | Quién la usa | Por qué no es viable | Alternativa |
|---|---|---|---|
| Inyectar `aria-label`, `role`, `aria-level`, `alt` en el DOM y mantenerlos con `MutationObserver` | axSGrease, userscripts, AltSpark, WebA11y | Requiere script de contenido en el navegador | Reescribir solo en el búfer (sección 2, puntos 1-4 y 10); el efecto para el usuario es el mismo salvo para otros lectores. |
| Eliminar de verdad la ventana de cookies u otros overlays para poder hacer clic en lo que hay debajo; desbloquear el desplazamiento (`overflow:hidden`) | Consent-O-Matic, IDCAC, uBlock con listas de «annoyances» | Hay que quitar nodos o inyectar CSS | Tiresias puede localizar y activar el botón «Rechazar/Aceptar» del banner (acción `activate` sobre reglas por CMP, al estilo de las reglas JSON de Consent-O-Matic) y, si no, ocultarlo solo en el búfer; recomendar al usuario Consent-O-Matic o la lista «Cookie notices» de uBlock Origin. |
| Añadir `tabindex` / forzar foco en elementos no enfocables; convertir `div` pulsables en `button` reales para que respondan a Intro/Espacio | userscripts | Cambiar foco real exige DOM | Activar por clic de ratón simulado en el centro del rectángulo o `Invoke` UIA (ya existe en el búfer); para escribir, mover el foco con `SetFocus` UIA cuando el nodo lo admita. |
| Reordenar el contenido, mover el `main` al principio, colapsar menús | Reader Mode, Readability, Just Read, Mercury Reader | Construyen un documento nuevo | El usuario puede activar la Vista de lectura de Firefox (F9) o el Modo lectura de Edge (F9) y Tiresias la lee como página normal; Tiresias puede ofrecer «ir al contenido principal deducido». |
| Cambiar estilos (contraste, tamaño de letra, fuentes, desactivar animaciones) | Stylus, modo lectura, extensiones de baja visión | CSS | Fuera del ámbito de un lector de pantalla; sugerir Stylus o los ajustes de accesibilidad del navegador. |
| Interceptar eventos de teclado de la página que roban atajos | userscripts | Requiere `addEventListener` en la página | Modo «pasar tecla» de Tiresias y, si el sitio es recurrente, reglas por sitio que remapeen atajos. |
| Corregir el `lang` de la página para la síntesis | extensiones | Atributo del DOM | Detección de idioma del texto en el propio Tiresias al hablar. |

## 4. Conclusiones para el complemento «Arreglo web»

- El modelo a imitar es Web Access for NVDA: reglas por sitio en JSON, criterios de selección (`role`, `tag`, `id`, `class`, `text`, `src`, `states`, ruta relativa) y un conjunto cerrado de mutaciones sobre el nodo del búfer (`button`, `link`, `heading.N`, `labelled`, `section`, `landmark.*`, `table.*`), más `customName`, `skip` y acciones automáticas (`moveto` al cargar).
- Encima de eso, una capa automática de heurísticas (sección 2) que se puede activar por defecto con un indicador de «deducido» y desactivar por sitio, en línea con JAWS (etiquetado automático de formularios, `title` de enlaces) y Chromium (`clickable`).
- Lo que no se puede hacer sin DOM (quitar overlays, forzar foco, reordenar) se delega: documentar Consent-O-Matic, la vista de lectura del navegador y las descripciones de imágenes de Chrome/Edge como complementos recomendados.
